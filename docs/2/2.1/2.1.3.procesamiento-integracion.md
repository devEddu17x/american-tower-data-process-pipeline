Apache Spark ejecutará las transformaciones tabulares y las agregaciones distribuidas. Apache Sedona se utilizará para las operaciones geoespaciales compatibles con las versiones seleccionadas. El procesamiento raster empleará las funciones y dependencias necesarias para reproyección, alineación, máscaras de calidad y extracción de estadísticas.

El pipeline comprenderá la validación de esquemas, normalización de tipos, identificación de duplicados, tratamiento documentado de faltantes, validación de coordenadas y geometrías, agregación territorial e integración temporal.

La integración utilizará una versión fija de los límites distritales y el código UBIGEO como identificador territorial. Los registros georreferenciados se relacionarán con los distritos mediante reglas espaciales documentadas. Antes de combinar las fuentes se controlará su granularidad para evitar uniones que multipliquen registros o conteos.

La tabla analítica tendrá como clave principal el distrito y el trimestre, dentro de cada versión publicada. Se conservarán indicadores de disponibilidad, antigüedad de las fuentes y suficiencia de las observaciones. La falta de mediciones no se sustituirá automáticamente por cero ni se interpretará como ausencia de servicio.

Para el entrenamiento se utilizarán únicamente características disponibles al momento de emitir cada pronóstico. Las fuentes sin historia verificable podrán alimentar la caracterización contemporánea o la priorización, pero no se trasladarán artificialmente a periodos anteriores.
